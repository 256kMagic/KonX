# KonX 0.27.1 — KonX-AI and Saved Provider Keys

2026-10-23. The contextual assistant is now **KonX-AI**, with improved encrypted provider-key management.

## Changes

- Rename Copilot to KonX-AI throughout current panels, tool actions, menus, status messages and guides. Existing conversations, evidence, reviewed outcomes and workspace references remain compatible.
- Retain provider API keys in the local encrypted store, reuse saved keys for requests and connection tests, and provide a clear deletion control for the selected provider.
- Preserve a newly entered key when validation or saving fails, and protect unsaved connection changes when closing or switching providers. Refresh an open KonX-AI panel after settings change so its test controls reflect the saved connection.
- Flush encrypted settings before publication, preserve the previous saved configuration on write failure, and retain ownership of pending temporary files or handles for cleanup retry. Pending cleanup blocks an update and keeps the window available if closing fails; key changes are rejected during shutdown.

The investigation found that the prior settings form cleared an entered key even when saving failed, and an already open contextual panel could retain stale connection status. Existing encrypted-key reuse was already implemented; these findings do not establish that a successfully saved key was deleted from the user's profile.

Read the [KonX-AI guide](../KONX_AI.md), [provider setup guide](../AI_KNOWLEDGE_GUIDE.md), and [user guide](../USER_GUIDE.md).
