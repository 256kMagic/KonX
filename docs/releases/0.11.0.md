# KonX 0.11.0 — Remote packet capture

Capture traffic on an existing Linux SSH connection and open the retained packets in KonX for readable traffic, SIP, and RTP analysis.

## Features

- Explicit interface, BPF filter, duration, and packet limits; no automatic collection when opening the tool.
- Dedicated SSH execution channel that leaves the original terminal available.
- Complete-record local PCAP streaming with usable partial results, bounded diagnostics, remote exit status, and explicit termination uncertainty.
- Verified result opening, collection-report export, and confirmed removal of registered captures.
- Tab/update guards and application-exit cleanup that wait for the capture channel and local file work.

See the [remote capture guide](../REMOTE_CAPTURE.md), [user guide](../USER_GUIDE.md), and [phased roadmap](../ROADMAP.md).

## Coverage

The selected host must already have Linux, tcpdump, GNU timeout, and capture permission. KonX does not install remote tools or elevate the account. Limits are 300 seconds, 100,000 packets, and 64 MiB per capture. Results describe the observed traffic and collection limits, not complete network coverage.

Automated SSH tests use a real local SSH transport with a synthetic capture command. A real Linux host running tcpdump has not been exercised. Some SSH servers do not forward stop signals or confirm process exit; GNU timeout provides an independent command bound. Retained PCAP files stay in the local profile after restart; result buttons belong to the current process.

The six inherited AI, Wi-Fi, and security-assessment findings listed in [0.6.3](0.6.3.md#known-issues) remain unchanged.
