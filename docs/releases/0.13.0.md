# KonX 0.13.0 — Capture comparison

Compare working and failing captures using source-backed DNS, TCP, and plaintext HTTP/1 observations.

## Features

- Select capture files or stopped Packet Capture tabs, or load a synthetic working/failing demo.
- Compare DNS answers, response codes and timing; TCP connection setup, resets and duplicate-sequence candidates; and HTTP status codes and response timing.
- Match service identities automatically or record an explicit pairing when addresses differ.
- Filter and page changed, unchanged, unknown, and unmatched observations; open the retained source packet on either side.
- Export comparison JSON, add it to an incident, or share only its summary with the AI workspace.
- Preserve absent packet timestamps through import, retained views, capture export, SIP export, and incident attachment. Report incomplete source records and bounded import coverage.
- Apply PCAPNG interface timestamp offsets, preserve DNS question classes, and keep mixed timing uncertainty from becoming a conclusive difference.
- Keep SIP call timing, RTP jitter, RTCP arrival times, and paired audio alignment unavailable when the required packet capture times are unknown; mono audio can still use the RTP media clock.
- Cancel sliced capture loading when its destination is cleared, so a surviving suffix cannot acquire complete-source coverage.

See the [capture comparison guide](../CAPTURE_COMPARISON.md), [user guide](../USER_GUIDE.md), and [completed phased roadmap](../ROADMAP.md).

## Coverage

Analysis is bounded to 50,000 packets and 64 MiB of packet bytes per side, with further flow, parsing, metric, and source-reference bounds. File selection is limited to 64 MiB. Reports preserve incomplete coverage and missing timestamps; they do not align independent capture clocks or infer a unique root cause.

HTTP comparison supports plaintext HTTP/1. TLS content, HTTP/2, HTTP/3, encrypted DNS, and DNS over TCP are outside this phase. Duplicate TCP sequence ranges are candidates rather than proof of packet loss. Unmatched services and missing replies are not classified as failures or removals.

Automated comparison verification uses synthetic captures and an isolated Electron workflow. Production network captures and real-device workflows remain field-test coverage.

The six inherited AI, Wi-Fi, and security-assessment findings listed in [0.6.3](0.6.3.md#known-issues) remain unchanged.
