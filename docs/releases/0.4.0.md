# KonX 0.4.0 test build

This Windows x64 test build adds AI & Knowledge to the Security Suite, wireless tools, and Mist/Marvis integration in [0.3.0](0.3.0.md).

- **Five provider connections:** OpenAI Responses, Claude Messages, Gemini generateContent, Nyquest chat, and a custom OpenAI-compatible Chat Completions endpoint. Each connection keeps a separate Windows-encrypted key and editable model ID. Nyquest defaults to its documented `nyquest/auto` router.
- **Operational offline library:** 46 original tool, networking, and vendor reference articles, with official source links and custom notes. A background worker maintains a local SQLite database of documents, chunks, and persistent TF-IDF cosine vectors. Search and reading do not need a cloud connection or AI key.
- **Explain with AI:** tool tabs, including Packet Capture, prepare bounded result snapshots in an AI tab. Context must be previewed and explicitly selected before sending. Answers appear as text alongside the local references supplied to the provider. AI suggestions do not execute tools or change settings.
- **Bounded requests:** cancellation on request/tab/app closure, stale-setting guards, redaction, fixed provider destinations, custom-endpoint credential binding, response-size limits, and no automatic retries.

## Try it

1. Open **AI & Knowledge** and browse the library before adding a key. Search for `RSSI`, `TLS`, `Unknown`, or a vendor name. Choose **Add note** to retain your own reference text.
2. Select a provider, review the model ID, enter your API key in the app, and choose **Save connection**. For Nyquest, create a personal API key in **app.nyquest.ai → Settings → API Keys**. For Custom, supply a compatible API base URL and model.
3. Run a tool, choose **Explain with AI**, review **Preview context**, and select **Send this context** if desired. Choose **Ask AI**. Inspect the answer and its references alongside the original evidence.

The selected provider receives your question and matching library excerpts. Optional tool context is sent only when selected. KonX does not automatically index terminal sessions, captures, editor files, credentials, or diagnostic logs. The local index uses word-based vectors, not neural embeddings, and makes no embedding API calls. Library articles are authored guidance rather than live vendor documentation or a vulnerability database.

Validation: **427 automated tests pass**, including 43 AI, library, integration, and desktop checks. Tests exercise all five provider adapters with simulated responses, real Windows credential encryption, background SQLite persistence and retrieval, an Electron ASAR worker, library transactions and failure states, context sharing, source references, cancellation, and 900×560/1400×880 layouts. All **74 application source files**, including the 46-article bundle, match the packaged archive. The unpacked application, portable executable, and installed Program Files application passed checks for the new AI/library workflows and the existing Security, Wi-Fi, and Mist tools across a restart. The installed archive matched the tested build; the normal user-profile background index initialized with all 46 bundled articles.

Provider adapters are validated with synthetic credentials and responses; no real provider API key or live paid generation was used. A live connection still depends on your provider account, key permissions, selected model, and billing. The installer and portable executable are unsigned test builds. This local build does not publish a GitHub Release.
