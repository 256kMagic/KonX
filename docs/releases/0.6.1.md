# KonX 0.6.1 — October 21, 2026

KonX 0.6.1 is the first public release with **Update KonX** on Home and under **Settings → Updates**. It carries the same updater features as the [local 0.6.0 test build](0.6.0.md), with a newer version so that build can exercise the update path after this complete release is published.

## Update features

- Portable copies support one-press checking of the latest stable GitHub release, downloading the matching Windows x64 executable with progress, size and SHA-256 verification, and installation/restart when work is safe. The installed button requires the unreleased fixes described below.
- Portable copies retain their original executable filename and location, with rollback if replacement or restart fails. With the unreleased fixes, installed updates retain their installation folder and per-user/all-users mode; all-users upgrades may require Windows administrator approval.
- Both distributions retain the existing Windows profile, settings, saved sessions, encrypted credentials, and Knowledge library. Save capture evidence before restarting; terminal connections and capture buffers are not restored.
- Unsaved documents, open Knowledge notes, active connections, transfers, captures, tools, and pending file operations block restart. The verified update stays ready while you finish the listed work, then **Install and restart** retries installation.
- Downloads can be cancelled and retried. Checks run only when requested: no GitHub token, startup polling, installation on ordinary exit, prerelease update, or downgrade is used.

## Upgrade path and release files

**Version 0.5.0 and earlier:** save your work, close KonX, then run `KonX-Setup-0.6.1.exe` or replace your portable executable with `KonX-0.6.1-portable.exe` once to gain the button.

**Local 0.6.0 portable build:** choose **Update KonX** to install 0.6.1. **Installed 0.6.0 or 0.6.1:** run the latest installer manually; the installed button needs a future release containing the fixes below. Source checkouts and unpacked application folders explain why in-place updating is unavailable.

The release bundle includes both executables, downloadable guides, these notes, and `SHA256SUMS.txt`. The updater rejects missing assets, unexpected sizes, and checksum mismatches. For a manual download, compare `Get-FileHash .\KonX-Setup-0.6.1.exe -Algorithm SHA256` with the manifest. These checks establish consistency with the GitHub release; the executables remain unsigned.

See [Updating KonX](../UPDATING.md) and the [user guide](../USER_GUIDE.md) for workflows, cancellation, and recovery.

## Known issues

Subsequent testing of a real all-users installation found two installed-updater defects: Electron's virtual ASAR filesystem makes the installed app appear unpacked, and the helper looks for the installation folder in the uninstall registry key instead of electron-builder's separate installation key. The original 0.6.0/0.6.1 installed button cannot complete a normal update. Portable updating works; installed copies need a manual upgrade to a future fixed release. Source fixes are unreleased.

The following six findings were reproduced during review of 0.5.0 and are **not fixed** by 0.6.0 or 0.6.1:

1. AI reference chunk boundaries can remove a credential's identifying label before redaction. Do not put sensitive credentials in custom Knowledge notes or rely on redaction to make them safe for AI requests.
2. Knowledge retrieval can select a matching chunk but omit its relevant passage when shortening the excerpt sent to AI.
3. Mixed WPA/WPA2 advertisements can lose evidence of weak WPA/TKIP alternatives in the Wi-Fi report.
4. Wi-Fi reports can omit a weak group cipher when the pairwise cipher is stronger.
5. HSTS checks can misclassify quoted `max-age` values and duplicate directives.
6. Unapplied Cisco macro bodies can be interpreted as active settings by the offline configuration assessment.

These findings are separate from the updater work. Verify affected assessments against the original evidence. AI and Mist tests use simulated provider responses; they do not establish live-account interoperability.

## Validation

At the 0.6.1 release commit (`41208e0`), all 482 automated tests passed, including updater download validation, cancellation, restart guards, renderer behavior, and 15 Windows helper tests with disposable executables. The installed and portable packages built successfully. All 81 packaged source files matched that release checkout and required runtime dependencies were present. Isolated unpacked and portable startup/restart checks passed, including encrypted credential persistence/removal and Knowledge notes.

The updater embedded in the preserved 0.6.0 portable build is byte-identical to the 0.6.1 downloader. Updater UI tests cover eight themes at a 900 × 560 viewport. Isolated checks of the final packaged apps confirmed version 0.6.1, portable detection, and Home/Settings updater controls. At publication, a complete public-release upgrade and a real installed NSIS upgrade had not yet been exercised; installed handoff tests used a disposable installer fixture.

Subsequent live testing on October 21 confirmed the portable 0.6.0 → 0.6.1 update and restart with the existing settings unchanged. The original installed 0.6.0 button failed because of the two defects above. Corrected source download/handoff components then installed the published 0.6.1 installer into the real all-users installation, with normal application shutdown and user-approved Windows elevation. KonX restarted as 0.6.1 in the same installation folder and mode; settings were byte-for-byte unchanged, and the Knowledge database integrity check passed. This component test does not establish that the published installed button works. No saved sessions, credentials, custom Knowledge notes, or Notepad recovery files were present in the live profile, so their retention was not exercised by this test. The corrected source passes 485 automated tests and remains unreleased.
